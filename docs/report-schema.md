# Report contract v1

The canonical machine-readable [JSON Schema](report.schema.json) is generated by `npm run build` from `src/report/schema.ts`. That module and `types.ts` have no Node-only imports. All output (including setup errors) uses the same envelope.

| Field | Meaning |
| --- | --- |
| schemaVersion | Numeric 1; consumers must reject unsupported versions |
| tool | `agent-eval-lab`, actual package version |
| run | UUID, UTC ISO start/end timestamps, elapsed milliseconds |
| project | Display name only, no dedicated absolute root path field |
| status / exitCode | passed/0, failed/1, error/2, cancelled/130 |
| score | Rounded pass ratio over all configured commands and active forbidden gate; null before evaluation |
| scoreComplete | False for unexecuted/error checks or global errors |
| summary | pass/fail/error/skipped, required/optional/total, optionalFailures counts |
| checks | Id, label, command or forbidden kind, required, status, duration, nullable exitCode/reason |
| git | null before analysis/on error; otherwise enabled/baseRef/baseSha, capture time, before-commands timing, changes, stats |
| warnings / errors | Stable category code, readable message, next-action hint |

Command records also contain actual executable/args, timedOut, signal, bounded stdout/stderr and outputTruncated. Strings can include sensitive output; review before sharing. A skipped check always has a reason. `forbidden-files` has matching path/pattern pairs, and is present only when enabled with a nonempty list.

Git changes preserve current path, nullable oldPath, Git status (or `untracked`), nullable additions/deletions and binary flag. Null is an unknown count, never an implicit zero. Summary line totals sum known tracked text only and `incomplete` signals unknown binary/untracked counts. A disabled Git record has no base and no changes, without a fabricated forbidden PASS.

The score includes optional checks; optional failures can coexist with overall passed. Any execution error forces error, even for an optional check. Required skipped forces error. Cancellation takes priority with exit 130. Error/skipped remain in the denominator, and early config errors have `checks: []`, `git: null`, `score: null`.

Reports are saved as UTF-8 JSON with a trailing newline. With `--json`, stdout parses to exactly the same object as the file on successful save. No ANSI/progress/child streaming is mixed in. If saving fails, stdout reflects the final write error; a previous report file may still describe an older run, so check the process exit and run id.

Init, argument, root-validation and configuration errors do not write reports or create directories. Their stdout envelope still carries the error, empty checks and null score. Process cleanup failures use the existing check `reason` and `error` status; cancellation retains overall `cancelled`/130 and incomplete scoring. There are no new schema fields.

Examples in `examples/reports` were generated from real commands with `npm run examples`; timestamps, UUIDs, durations, and captured temporary paths are deliberately not invented or fixed. They are evidence of those fixture runs, not current claims about another project.
