# Architecture and decisions

One npm package, ESM output, TypeScript strict mode, Node >=22.12.0. Node 22 and 24 are CI targets; the measured local platform is Windows with Node 24.16.0. Package versions are pinned in package.json and package-lock.json. Consumers run compiled JS without a source loader or installation build.

- `src/cli`: argument contract, TTY policy, interactive setup, SIGINT and output orchestration. Only this boundary sets process.exitCode.
- `src/config` and `src/detect`: YAML + strict Zod validation; static evidence collection and safe npm command suggestions.
- `src/core`: result envelope, sequential evaluation and aggregation. No prompts, terminal coloring, or process.exit.
- `src/process` and `src/git`: bounded process output/cleanup, read-only Git calls, NUL parsing and before-command snapshot.
- `src/report`: pure types and browser-compatible Zod schema, separate serialization, terminal formatting, and filesystem writer.

The report object is finalized once, then saved and rendered. A save failure updates the final stdout report and exit code to 2; the unavailable file cannot of course contain that failure. Early init/argument/root/config errors use the same stdout envelope with no checks and null score, but do not save or create directories. Persistence requires a valid run root and configuration. Atomic replacement uses a temporary file in the target directory. There is no promise of durability across machine crashes, nor a general filesystem sandbox.

Libraries: YAML parses config without executing code; Zod validates unknown fields and runtime types; jsonc-parser reads tsconfig comments without importing the project; minimatch provides a constrained documented glob dialect. The process invocation boundary maps a recognized Windows npm.cmd installation to Node plus npm-cli.js, rejects unknown npm shims and unsafe batch argument combinations, and delegates ordinary execution to cross-spawn. Node built-in filesystem/process/readline APIs cover other boundaries. Vitest is development-only. Runtime libraries are production dependencies.

Primary implementation references: [Node child processes](https://nodejs.org/api/child_process.html), [cross-spawn](https://github.com/moxystudio/node-cross-spawn), [minimatch](https://github.com/isaacs/minimatch), [Vitest](https://vitest.dev/guide/). Versions were actually installed and locked; newest-version status is not claimed.

Process cleanup is best effort across OS boundaries: POSIX child groups, Windows taskkill trees. Windows resolves taskkill from SystemRoot rather than PATH, waits at most 2 seconds for it, then falls back to direct-child termination on failure. Exit confirmation waits are bounded to 1 second per attempt, with a 500ms pipe-drain deadline. Diagnostics distinguish direct-child exit from unconfirmed tree cleanup; an unconfirmed check is error. Cancellation retains unexecuted checks as skipped and overall exit 130. A Git error does not prevent independent commands, but forces overall error and errors any active forbidden gate. Report statistics are not scored.

Git diff name/status and numstat plus ls-files are collected before commands. This is a bounded read (16 MiB per Git output, 15 s per Git operation), not a transaction against concurrent external edits. Exceeding limits is an error rather than partial invented success. Working-tree paths are root-relative and normalized by Git. Report paths are resolved by CLI against the evaluated root. No broad ignored-file reads, global Git identity changes, or index/branch writes occur.

In-scope assume-unchanged/skip-worktree flags produce a Git error without modifying the index. When an index-deleted path has been restored as untracked, its base blob and final disk content are compared in a private temporary directory using read-only Git operations. `check-attr` and `hash-object` (without `-w`) verify text normalization; no objects or index entries are written. Automatic text normalization preserves a pre-existing CRLF base blob, while explicit text/eol attributes request normalization. Unsupported clean filters/working-tree encodings produce errors before filter execution. An identical restoration disappears; an edited restoration is one modification, not deletion plus addition. If a staged rename's original path is restored, the destination becomes a final addition and the restored source is compared independently. The comparison is limited to 16 MiB, and only the output line terminator is removed from Git directory prefixes. Long command timeouts are chunked rather than passed to Node as an overflowing timer value. Line-oriented prompts avoid raw-mode operations that restricted Windows consoles can reject.

No reusable plugin framework or public API stability promise is introduced. The stable integration surface for a future viewer is the versioned JSON data contract.
